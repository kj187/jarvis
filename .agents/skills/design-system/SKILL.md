# Jarvis — Design System workflow

The normative rules are in `docs/design-system.md` (one guide for app, docs
site, screenshots, videos). This file is the short workflow: which surface
you are on, where the value lives, what to run before you commit. If the
guide and the code disagree, the code wins — fix the guide in the same commit.

---

## 1. Name the surface first

| Surface | Density | Where it lives |
|---|---|---|
| Product UI | compact | `frontend/src/components/**`, `index.css` |
| Documentation site | comfortable | `website/.vitepress/theme/**` |
| Media (screenshots, video, social) | own layouts | `frontend/e2e/screenshots/**`, `frontend/e2e/video/**` |

## 2. Reuse before you add

- **Colour** — only semantic tokens: neutrals (`bg-card`, `text-muted-foreground`), status roles
  (`bg-critical-soft`, `text-warning-fg`, `border-claim-edge`, `bg-info-solid`; roles
  critical/warning/info/neutral/success/attention/claim) and interaction tokens
  (`ring`, `border-control`, `text-link`, `bg-selected`). Never a raw Tailwind palette class, hex or `rgb()`.
- **Radius** — `rounded-compact|control|surface|overlay|pill`, never `rounded-md`.
- **Type** — Inter (`font-sans`) for everything, `font-mono` only for matchers/code/IDs; sizes are roles.
- **Controls** — the primitives in `components/ui/`; a text field's edge is `border-control`.
- **Overlays** — one primitive per role: `Dialog` (modal), `Sheet` (side panel), `Popover` (non-modal,
  interactive), `Tooltip`/`InfoHint` (short, non-interactive). Never a hover-only surface.
- **Icons** — Lucide, 2 px outline, every icon-only control has an `aria-label`.

A genuinely new colour, role or radius is a change to `design/tokens.json`, not a one-off class.

## 3. Values live in one place

| You change | Edit | Then run |
|---|---|---|
| A colour or radius value | `design/tokens.json` | `node scripts/design-tokens.mjs` (writes app CSS, docs-site variables, video palette) |
| The logo | `design/assets/logo.svg` | `python3 scripts/logo-assets.py` (PNG, favicons, mono variants) |
| A colour in the guide illustrations | (generated) | `python3 scripts/design-guide-assets.py` |

Never edit a generated file (`generated/tokens.css`, `generated-tokens.css`, `generated-theme.ts`,
`logo.png`, favicons). The pre-commit hook and CI run the `--check` modes and `check-design-drift.mjs`.

## 4. Checklist before you commit

1. **Both themes** — look at the change in dark and light. Same meaning, same role; no `theme === 'light'` branch for colour.
2. **Contrast** — text 4.5:1, UI boundaries and state indicators 3:1. Meaningful text is never dimmed with an
   opacity suffix. New token pairs get a case in `frontend/src/lib/themeTokens.test.ts`.
3. **Keyboard** — everything reachable and operable; visible 2 px focus ring; Escape closes overlays and
   returns focus; status never by colour alone.
4. **Motion** — a new animation needs a `prefers-reduced-motion` answer in the same change.
5. **States** — default, hover, focus, active, disabled, loading, error.
6. **Tests** — `pnpm build && pnpm lint && pnpm test:unit` in the dev container; UI behaviour → an E2E spec
   (`bash scripts/e2e-run.sh test none`); drift → `node scripts/check-design-drift.mjs`.

## 5. Media

- **Screenshots** come from the fixture stack (`docs/testing-e2e.md`), dark by default; only hero and
  overview images are dark/light pairs. Regenerate with `make e2e-screenshots` after a visual change.
- **Videos** use `frontend/e2e/video/theme.ts` (product blue, coral accent); see the `release-video` skill.
- **Social / Open Graph** images are generated by `frontend/e2e/screenshots/none/social-templates.screenshot.spec.ts`
  from the same tokens and the logo.
- Every image has alt text that says what it shows.

## 6. Keep the docs in step

A visual rule change updates `docs/design-system.md`; a new primitive or token file updates
`.agents/architecture/frontend-tree.md` or `frontend-components.md`; new checks update `.agents/testing.md`
(mapping: `.agents/doc-sync.md`, AGENTS.md → Workflow Rule 6).
